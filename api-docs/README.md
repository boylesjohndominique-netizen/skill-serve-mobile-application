# SkillServe API Documentation

This directory is the mobile integration package for the implemented Laravel API. Use this package as the integration source of truth; it documents routes that exist in the backend and does not define speculative endpoints.

## Contents

- `openapi.json` is the OpenAPI 3 specification generated by the Laravel backend.
- `modules/` contains endpoint-by-endpoint Markdown documentation grouped by backend module.
- `MODULES.md` is the clickable module index.
- `generate.php` regenerates the Markdown files from `backend/storage/api-docs/api-docs.json`.

## Base URL

The local development API is `http://localhost:8000`. Every route below includes its `/api` prefix. Configure the production base URL in the Flutter environment; do not hard-code the local URL in release builds.

## Authentication

The API uses Laravel Sanctum bearer tokens. Send the token on protected requests:

```http
Authorization: Bearer <token>
Accept: application/json
Content-Type: application/json
```

There are two account surfaces:

- **Admin API**: `/api/auth/*` and the administrative modules. Admin login tokens require the `admin:auth` ability where documented.
- **Client API**: `/api/client/v1/*`. Client tokens are intended for mobile customers and protected client routes also require an active client account.

Public endpoints explicitly say `Public`. Do not send admin credentials to client endpoints or client credentials to admin endpoints.

## Response envelope

JSON responses normally use this envelope:

```json
{
  "success": true,
  "message": "Request successful.",
  "data": {},
  "errors": null,
  "meta": []
}
```

Paginated responses put pagination information under `meta.pagination`. Validation failures use `success: false`, `data: {}`, and an `errors` object keyed by field. The documented status codes and examples are in each module file and the OpenAPI spec.

## Common errors

- `401`: missing, expired, revoked, or wrong-surface bearer token.
- `403`: authenticated account lacks the required permission or policy authorization.
- `404`: route model/resource was not found.
- `422`: request validation or a business-rule validation failure.
- `429`: rate limit exceeded. Login is limited to 5 attempts per minute per IP; the general API limit is 60 requests per minute per user/IP.

## Mobile-specific flow

1. Register or log in through `Client Authentication`.
2. Store the returned access token securely and send it as a bearer token.
3. Refresh the client token with `/api/client/v1/auth/refresh` when required by the response.
4. On `401`, clear the session and authenticate again; logout and password changes revoke sessions.
5. Use the public `Client Marketplace` routes for catalog discovery and protected client routes for bookings, reviews, notifications, support, and booking messages.

## Regenerating

From the repository root, after Laravel has regenerated its spec:

```bash
docker compose exec backend php artisan l5-swagger:generate
php api-docs/generate.php
```

The generated files intentionally retain the backend’s examples and response descriptions. If an endpoint changes, update its Laravel OpenAPI attributes and validation rules first, regenerate, then review the resulting module file.

## Realtime notifications

The client notification event is broadcast on the private channel `App.Models.User.{id}` as `client.notification.created`. Channel authentication uses the API bearer token. The notification inbox endpoints remain the source of truth after reconnecting.
