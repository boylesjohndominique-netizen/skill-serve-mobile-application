SECTION 6 — APP STRATEGY
--------------------------------------------------------------------------------
ONE Flutter app, role-based:
  • On login/registration the user picks or is assigned a role.
  • Navigation shells differ by role (Client bottom nav vs Provider bottom nav).
  • Shared code: auth, models, repositories, chat, notifications, design system.

User flows to support end-to-end:
  CLIENT:  Register/Login → Discover → Provider profile → Book (4 steps) →
           Manage bookings → Chat → Pay → Review → File report
  PROVIDER: Register/Login → Complete profile + Verification (upload docs) →
           Add services → Upload portfolio → Accept bookings → Chat →
           Complete job → Get paid → Earn badges

SECTION 11 — CRITICAL WORKFLOWS (STATE MACHINES)
--------------------------------------------------------------------------------
BOOKING LIFECYCLE (client + provider):
  pending ──provider accepts──▶ confirmed ──provider starts──▶ in_progress
  pending ──client cancels──▶ cancelled
  in_progress ──provider completes──▶ completed ──client reviews──▶ review
  any ──client disputes / report filed──▶ disputed ──admin resolves──▶
  completed or cancelled
  Rules: client can cancel pending/confirmed; provider can accept/decline
  pending, start confirmed, complete in_progress. Each transition pushes a
  notification to the other party and adds a timeline entry.

VERIFICATION FLOW (provider):
  pending ──admin approves──▶ verified (seal emerald)
  pending ──admin rejects──▶ rejected ──provider resubmits──▶ pending
  pending ──admin requests resubmission──▶ resubmission_requested
  ──provider resubmits──▶ pending
  Only verified providers can go fully public (featured/leaderboard qualify).

PAYMENT FLOW:
  Booking confirmed → payment pending → paid (GCash/Maya/Card/Cash) →
  on refund/dispute resolution → refunded.
  Provider sees earnings only for paid/refunded-tracked payments.

RECOGNITION RULES (computed automatically; see Section 4 badge criteria).
  Badges appear on provider profile (client app) and in provider's
  Recognition screen. Admin can feature providers; featured providers appear
  in the client Discover "Featured" strip.

NOTIFICATIONS:
  Admin broadcasts target audience: all | clients | providers. Mobile
  registers for FCM topics per audience bucket + user-specific topics
  (booking updates, verification updates, payouts).
